5.5.2 Frontend, API Gateway và Auth

Các bài kiểm tra này đi qua đường request chính từng lớp một, để khi lỗi thì chỉ thẳng vào lớp bị hỏng.

#Kiểm traCách làmKết quả mong đợiTrạng thái
T1Lambda → AuroraTest event auth-login-db-smoke trên Lambda console (POST /auth/login, email không tồn tại)statusCode: 401 “invalid credentials”, không có P1000, P1001, PrismaClientInitializationError, Can't reach database hay relation "users" does not existPass
T2Static hosting + SPA fallbackMở trực tiếp http://<frontend-bucket>.s3-website-ap-southeast-1.amazonaws.com/loginTrang đăng nhập hiển thị (không phải 404 của S3)Pass
T3Browser → API Gateway → Lambda → AuroraTrên /login, mở DevTools → Network và đăng nhập bằng email không tồn tạiPOST /auth/login → 401 {"error":"Invalid credentials"}, không có lỗi CORSPass
T4Mọi route đều có integrationAPI Gateway → Integrations → Attach integrations to routesMỗi route hiện target Lambda/HTTP; không route nào trả {"message":"Not Found"}Đã kiểm tra cho từng service khi deploy
T5Endpoint nội bộ không publicGET https://<api-id>.execute-api.ap-southeast-1.amazonaws.com/internal/anything và /auth/internal/users/batch404 Not Found từ API Gateway (không có route này)Đưa vào lượt E2E cuối
T6Route AI bị rate limitGửi nhiều POST /ai/ask trong một giâyMột số trả 429 Too Many Requests; frontend hiện thông báo “quá nhiều yêu cầu” thay vì retry liên tụcĐưa vào lượt E2E cuối
T7Đăng nhập thật và hồ sơĐăng ký, xác minh, đăng nhập, mở profile/onboardingCác route /auth/* và User trả 200, dữ liệu lưu trong AuroraĐưa vào lượt E2E cuối
